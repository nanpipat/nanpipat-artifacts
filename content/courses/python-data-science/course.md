## เมื่อยอดขาย 200 แถวพูดพร้อมกัน เราต้องช่วยจัดคิวให้ข้อมูล

ลองนึกภาพว่าเราเป็นเจ้าของร้านกาแฟ สิ้นเดือนพนักงานส่งไฟล์ยอดขายมาให้ ตารางยาวสองร้อยแถวเต็มไปด้วยวันที่ ชื่อเมนู ประเภทเครื่องดื่ม ราคา และจำนวนแก้ว

เราถามคำถามง่าย ๆ ว่า “เมนูไหนขายดีที่สุด?”

ทุกแถวในตารางเหมือนยกมือพร้อมกันแล้วตะโกนข้อมูลของตัวเอง เสียงดังมาก แต่ยังไม่มีคำตอบ

Data Science ช่วยจัดคิวให้ข้อมูล เราโหลดตาราง ตรวจว่ามีอะไรอยู่ ทำความสะอาดสิ่งผิดปกติ รวมข้อมูลที่เกี่ยวข้อง แล้วเปลี่ยนผลเป็นข้อความหรือกราฟที่คนใช้ตัดสินใจได้

บทความนี้ใช้ Python, Pandas และ Matplotlib พาเดินตั้งแต่ CSV แถวแรก ไปจนถึง Mini Project วิเคราะห์ร้านกาแฟ

## 1. Data Science คือการเดินจากข้อมูลไปสู่การตัดสินใจ

Data Science ไม่ได้หมายถึงการสร้างกราฟสีสวยเพียงอย่างเดียว และไม่ใช่การโยนข้อมูลเข้า AI แล้วรอคำตอบแบบจับฉลาก

หัวใจของมันคือการใช้ข้อมูลตอบคำถามอย่างมีเหตุผล

วงจรพื้นฐานมีหน้าตาประมาณนี้

```text
ตั้งคำถาม
  ↓
เก็บหรือโหลดข้อมูล
  ↓
ตรวจและทำความสะอาด
  ↓
วิเคราะห์
  ↓
สื่อสารผลลัพธ์
  ↓
ตัดสินใจหรือถามคำถามต่อ
```

คำถามต้องมาก่อนคำสั่ง ถ้าเราเปิดไฟล์แล้วเริ่มสร้างกราฟทุกคอลัมน์ทันที เราอาจได้ผลงานหน้าตาคึกคัก แต่ยังไม่รู้ว่าจะใช้ทำอะไร

สำหรับร้านกาแฟ คำถามอาจเป็น

- เมนูไหนขายดีที่สุด
- เครื่องดื่มร้อนกับเย็นมีราคาเฉลี่ยต่างกันแค่ไหน
- ยอดขายเปลี่ยนตามวันหรือไม่
- ราคาเกี่ยวข้องกับจำนวนที่ขายได้หรือเปล่า
- มีข้อมูลหายหรือบันทึกซ้ำจนทำให้ผลเพี้ยนไหม

เมื่อคำถามชัด เราจึงเลือกข้อมูลและวิธีวิเคราะห์ได้ถูก

### Data, Information และ Insight ต่างกันอย่างไร

`Latte, เย็น, 85 บาท, 3 แก้ว` คือข้อมูลหนึ่งแถว

“Latte ขายรวม 430 แก้วในเดือนนี้” คือข้อมูลที่ผ่านการรวมจนอ่านง่ายขึ้น

“Latte เย็นขายดีช่วงบ่าย จึงควรเตรียมนมเพิ่มก่อนเวลา 13:00 น.” คือ Insight ที่เชื่อมข้อมูลเข้ากับการตัดสินใจ

กราฟจึงไม่ใช่เส้นชัย ถ้าคนดูกราฟแล้วไม่รู้ว่าจะคิดหรือทำอะไรต่อ งานวิเคราะห์ยังเดินมาไม่ถึงปลายทาง

> **ภาพจำแบบเร็ว:** Data Science คือการเปลี่ยน “สิ่งที่เกิดขึ้น” ให้กลายเป็น “สิ่งที่เราเข้าใจและนำไปใช้ได้”

## 2. Library กล่องเครื่องมือที่ช่วยให้เราไม่ต้องเริ่มจากศูนย์

ใน Python 101 เราเขียนคำสั่งพื้นฐานด้วยตัวเอง เมื่อเริ่มทำ Data Science เราจะใช้ Library ที่คนอื่นสร้างและทดสอบไว้แล้ว

เปรียบเหมือนการเข้าครัว เราไม่ต้องสร้างเตา หล่อกระทะ และแกะสลักช้อนก่อนทำข้าวผัด เราเริ่มจากเครื่องมือที่มีแล้วมาสนใจวัตถุดิบกับรสชาติแทน

Library สำคัญในบทนี้ ได้แก่

- **Pandas** สำหรับข้อมูลตาราง
- **NumPy** สำหรับข้อมูลตัวเลขและ Array
- **Matplotlib** สำหรับสร้างกราฟ
- **Seaborn** สำหรับกราฟเชิงสถิติที่ใช้งานสะดวกขึ้น

นำ Pandas เข้ามาใช้ด้วย `import`

```python
import pandas as pd
```

`pd` เป็นชื่อย่อที่ชุมชนใช้กันทั่วไป หลังจากนี้เราเขียน `pd.DataFrame()` แทน `pandas.DataFrame()`

### DataFrame ตารางที่เขียนคำสั่งคุยด้วยได้

DataFrame คล้าย Sheet ใน Excel มีแถว มีคอลัมน์ และมีชื่อคอลัมน์ แต่เราใช้โค้ดสั่งให้มันเลือก กรอง รวม และคำนวณซ้ำได้

```python
import pandas as pd

data = {
    "ชื่อ": ["ไอซ์", "มิ้น", "บีม", "แพร"],
    "คะแนน": [85, 92, 78, 95],
    "สาขา": ["CS", "IT", "CS", "DS"],
}

df = pd.DataFrame(data)
print(df)
```

Dictionary แต่ละ Key กลายเป็นชื่อคอลัมน์ และ List แต่ละชุดกลายเป็นข้อมูลในคอลัมน์นั้น

ชื่อ `df` ย่อจาก DataFrame พบได้บ่อยในตัวอย่าง แต่ในโปรเจกต์ที่มีหลายตาราง ควรตั้งชื่อให้ชัดขึ้น เช่น `sales_df` หรือ `students_df`

## 3. CSV ประตูทางเข้าของข้อมูลจำนวนมาก

CSV ย่อจาก Comma-Separated Values เป็นไฟล์ข้อความที่เก็บข้อมูลตาราง แต่ละบรรทัดคือหนึ่งแถว และค่าถูกคั่นด้วยเครื่องหมาย เช่น comma

โหลดไฟล์ด้วย Pandas ได้ในบรรทัดเดียว

```python
import pandas as pd

df = pd.read_csv("coffee_shop.csv")
```

หลังโหลด อย่าเพิ่งรีบวิเคราะห์ ให้ตรวจของที่เพิ่งรับมาก่อน เหมือนเปิดกล่องพัสดุแล้วดูว่าสินค้าครบหรือไม่ แทนที่จะเซ็นรับแล้วนำไปขายทันที

### `head()` ดูตัวอย่างแถวแรก

```python
print(df.head())
print(df.head(10))
```

ค่าเริ่มต้นแสดง 5 แถว เราใส่จำนวนที่ต้องการได้

### `shape` ดูขนาด

```python
print(df.shape)
```

ผลเช่น `(200, 5)` หมายถึง 200 แถว 5 คอลัมน์ สังเกตว่า `shape` เป็น Attribute จึงไม่มีวงเล็บท้าย

### `info()` ตรวจชนิดและข้อมูลที่หาย

```python
df.info()
```

คำสั่งนี้ช่วยดูชื่อคอลัมน์ ชนิดข้อมูล จำนวนค่าที่ไม่ว่าง และหน่วยความจำโดยคร่าว

### `describe()` ดูสถิติพื้นฐาน

```python
print(df.describe())
```

สำหรับคอลัมน์ตัวเลข เราจะเห็นจำนวนข้อมูล ค่าเฉลี่ย ส่วนเบี่ยงเบน ค่าต่ำสุด ค่าสูงสุด และตำแหน่ง Quartile

### คำถามนักสืบก่อนเริ่มวิเคราะห์

ลองตอบให้ได้ว่า

1. ตารางมีขนาดเท่าไร
2. แต่ละคอลัมน์หมายถึงอะไร
3. ชนิดข้อมูลถูกต้องหรือไม่
4. มีข้อมูลหายตรงไหน
5. ช่วงค่าดูสมเหตุสมผลหรือไม่

ถ้าคอลัมน์ราคาเฉลี่ย 75 บาท แต่ค่าสูงสุดเป็น 75,000 บาท เราควรหยุดทักทายข้อมูลแถวนั้นก่อนสร้างกราฟ

## 4. เลือก Filter และ Sort เพื่อหยิบเฉพาะสิ่งที่อยากดู

DataFrame ทั้งก้อนอาจใหญ่เกินไป เราจึงต้องเลือกคอลัมน์และแถวที่เกี่ยวกับคำถาม

### เลือกหนึ่งคอลัมน์

```python
menu = df["เมนู"]
print(menu.head())
```

### เลือกหลายคอลัมน์

```python
summary = df[["เมนู", "ราคา", "จำนวน"]]
print(summary.head())
```

สังเกตวงเล็บเหลี่ยมสองชั้น ชั้นนอกเลือกข้อมูลจาก DataFrame ชั้นในคือ List ของชื่อคอลัมน์

### Filter แถวด้วยเงื่อนไข

```python
expensive = df[df["ราคา"] > 100]
print(expensive)
```

ส่วน `df["ราคา"] > 100` สร้างชุดค่า `True` และ `False` แล้ว DataFrame เลือกเฉพาะแถวที่เป็น `True`

ใช้หลายเงื่อนไขได้

```python
hot_and_expensive = df[
    (df["ประเภท"] == "ร้อน") &
    (df["ราคา"] > 70)
]
```

ในเงื่อนไข Pandas ใช้ `&` แทน `and` และแต่ละเงื่อนไขควรมีวงเล็บครอบ

### เรียงข้อมูลด้วย `sort_values()`

```python
highest_price = df.sort_values("ราคา", ascending=False)
print(highest_price.head())
```

`ascending=False` เรียงจากมากไปน้อย ถ้าไม่ระบุ Pandas จะเรียงจากน้อยไปมาก

การ Filter ตอบว่า “ขอเฉพาะใคร” ส่วนการ Sort ตอบว่า “ให้ใครขึ้นมาก่อน”

## 5. GroupBy รวมเสียงหลายแถวให้ตอบเป็นกลุ่ม

ถ้าอยากรู้ยอดขายรวมของแต่ละเมนู เราไม่ต้องนั่งบวกทีละแถว ใช้ `groupby()` จัดแถวที่มีเมนูเดียวกันเข้ากลุ่ม แล้วสรุปค่าด้วย `sum()`

```python
sales_by_menu = (
    df.groupby("เมนู")["จำนวน"]
      .sum()
      .sort_values(ascending=False)
)

print(sales_by_menu)
```

อ่านจากซ้ายไปขวาได้ว่า

1. จัดกลุ่มตามเมนู
2. สนใจคอลัมน์จำนวน
3. รวมจำนวนในแต่ละกลุ่ม
4. เรียงจากมากไปน้อย

ถ้าอยากรู้ราคาเฉลี่ยแยกตามประเภทเครื่องดื่ม

```python
average_price = df.groupby("ประเภท")["ราคา"].mean()
print(average_price)
```

GroupBy คล้ายให้ลูกค้าในร้านย้ายไปนั่งโต๊ะตามเมนูที่สั่ง แล้วเราเดินนับยอดแต่ละโต๊ะ แทนการวิ่งถามทุกคนใหม่ทีละคน

ฟังก์ชันสรุปที่ใช้บ่อย ได้แก่

- `sum()` ผลรวม
- `mean()` ค่าเฉลี่ย
- `count()` จำนวนรายการที่ไม่ว่าง
- `size()` จำนวนแถวในกลุ่ม
- `min()` และ `max()`

ต้องเลือกให้ตรงคำถาม “เมนูขายดี” อาจหมายถึงจำนวนแก้วรวม ไม่ใช่จำนวนบิลหรือรายได้รวม แต่ละนิยามให้คำตอบต่างกัน

## 6. Data Cleaning งานหลังร้านที่กำหนดคุณภาพหน้าร้าน

ข้อมูลจริงไม่ค่อยมาในชุดเรียบร้อยพร้อมโบว์ บางช่องว่าง บางแถวซ้ำ บางตัวเลขถูกเก็บเป็นข้อความ และบางค่าหลุดไกลเหมือนคนกดศูนย์เกินมาสามตัว

ถ้าใช้ข้อมูลสกปรก ผลวิเคราะห์ก็รับปัญหานั้นต่อไป กราฟสวยไม่ช่วยให้เลขผิดกลายเป็นเลขถูก

### ตรวจข้อมูลหาย

```python
print(df.isnull().sum())
```

ผลลัพธ์บอกจำนวนช่องว่างในแต่ละคอลัมน์

### ลบแถวที่ขาด

```python
df_without_missing = df.dropna()
```

วิธีนี้ง่าย แต่เราเสียข้อมูลทั้งแถว จึงต้องคิดว่าข้อมูลที่เหลือเพียงพอหรือไม่ และการหายเกิดแบบสุ่มจริงหรือเปล่า

### เติมค่าที่หาย

```python
average_quantity = df["จำนวน"].mean()
df["จำนวน"] = df["จำนวน"].fillna(average_quantity)
```

การเติมค่าเฉลี่ยช่วยรักษาจำนวนแถว แต่ไม่ได้เหมาะทุกกรณี ถ้าค่ากระจายมากหรือมี Outlier ค่าเฉลี่ยอาจไม่เป็นตัวแทนที่ดี เราอาจใช้ Median, Mode หรือกติกาจากธุรกิจแทน

### ตรวจข้อมูลซ้ำ

```python
print(df.duplicated().sum())
df = df.drop_duplicates()
```

ก่อนลบ ต้องถามว่ารายการซ้ำคือ Error จริงหรือเป็นลูกค้าซื้อเมนูเดิมสองครั้ง ข้อมูลที่หน้าตาซ้ำไม่ได้แปลว่าเป็นรายการซ้ำเสมอไป

### แปลงชนิดข้อมูล

```python
df["วันที่"] = pd.to_datetime(df["วันที่"], errors="coerce")
df["ราคา"] = pd.to_numeric(df["ราคา"], errors="coerce")
```

`errors="coerce"` เปลี่ยนค่าที่แปลงไม่ได้ให้เป็นค่าหาย จากนั้นเราค่อยตรวจและตัดสินใจจัดการ

### Cleaning Log สมุดบันทึกว่าเราแตะอะไรไปบ้าง

ทุกครั้งที่แก้ข้อมูล ควรบันทึกเหตุผล เช่น

- ลบแถวซ้ำ 3 แถว เพราะมี Transaction ID เดียวกัน
- เติมจำนวนที่หายด้วย Median แยกตามเมนู
- แปลงราคาเป็นตัวเลข และพบค่าแปลงไม่ได้ 2 แถว

Data Cleaning ที่ไม่มีบันทึกเหมือนเชฟปรุงอาหารหลังม่านแล้วบอกว่า “เชื่อผม อร่อยแน่” คนตรวจงานต้องรู้ว่าวัตถุดิบถูกเปลี่ยนอย่างไร

## 7. Visualization เลือกกราฟให้ตอบคำถาม ไม่ใช่เลือกเพราะสีสวย

กราฟช่วยให้สมองเห็นรูปแบบได้เร็วกว่าการอ่านตัวเลขยาว ๆ แต่กราฟแต่ละชนิดเหมาะกับคำถามต่างกัน

### Bar Chart เปรียบเทียบระหว่างกลุ่ม

ใช้ตอบว่าเมนูไหนขายมากกว่า หรือสาขาไหนทำยอดได้สูงกว่า

```python
import matplotlib.pyplot as plt

sales_by_menu = df.groupby("เมนู")["จำนวน"].sum()

plt.figure(figsize=(8, 4))
plt.bar(sales_by_menu.index, sales_by_menu.values)
plt.title("ยอดขายรวมแยกตามเมนู")
plt.ylabel("จำนวนแก้ว")
plt.xticks(rotation=30)
plt.tight_layout()
plt.show()
```

### Line Chart ดูแนวโน้มตามเวลา

```python
daily_sales = df.groupby("วันที่")["จำนวน"].sum()

plt.figure(figsize=(10, 4))
plt.plot(daily_sales.index, daily_sales.values, marker="o")
plt.title("ยอดขายรายวัน")
plt.ylabel("จำนวนแก้ว")
plt.xticks(rotation=45)
plt.tight_layout()
plt.show()
```

### Scatter Plot ดูความสัมพันธ์ของสองตัวแปร

```python
plt.scatter(df["ราคา"], df["จำนวน"], alpha=0.6)
```

## 9. กับดักที่ทำให้กราฟดูดีแต่คำตอบไม่น่าเชื่อ

### ไม่ตรวจหน่วย

คอลัมน์หนึ่งอาจเป็นบาท อีกคอลัมน์เป็นพันบาท ถ้ารวมกันตรง ๆ ตัวเลขจะดูใหญ่และผิดอย่างมีระเบียบ

### ใช้ค่าเฉลี่ยกลบ Outlier

ลูกค้าส่วนใหญ่ซื้อ 1 ถึง 3 แก้ว แต่มีรายการหนึ่ง 500 แก้ว ค่าเฉลี่ยจะถูกดึงสูง ควรดู Median และ Distribution ร่วมด้วย

### สรุปเหตุและผลจากความสัมพันธ์

ยอดขายไอศกรีมกับจำนวนคนเล่นน้ำอาจเพิ่มพร้อมกัน เพราะอากาศร้อน ไม่ได้หมายความว่าไอศกรีมทำให้คนกระโดดลงสระ

### เลือกช่วงข้อมูลที่เข้าข้างคำตอบ

การเลือกเฉพาะสัปดาห์ที่ยอดขายดีอาจทำให้แนวโน้มดูสวย แต่ไม่สะท้อนทั้งเดือน ระบุช่วงเวลาและเหตุผลที่เลือกเสมอ

### Cleaning จนข้อมูลสะอาดเกินจริง

ถ้าเราลบทุกแถวที่ดูแปลก อาจลบเหตุการณ์จริงที่สำคัญออกไปด้วย Outlier บางตัวคือ Error แต่บางตัวคือวันที่ร้านมีอีเวนต์ใหญ่

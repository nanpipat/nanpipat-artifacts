# สร้าง .NET 5.0 Web API Project แล้วจับยัดลง Docker กันเถอะ

บทความนี้เริ่มต้นในปี 2020 ตอน .NET 5 ยังใหม่เอี่ยม กลิ่น SDK เหมือนเพิ่งแกะกล่อง เป้าหมายของเราง่ายมาก: สร้าง Web API หนึ่งตัว แล้วแพ็กลง Docker ให้รันได้เหมือนกันทุกเครื่อง

แนวคิดนี้ยังใช้ได้ดีในปี 2026 แต่ตัวเวอร์ชันเปลี่ยนไปแล้วครับ **.NET 5 หมดระยะสนับสนุนและไม่ควรใช้เริ่มโปรเจกต์ใหม่** ปัจจุบันควรเลือก .NET รุ่นที่ยังได้รับการสนับสนุน เช่น .NET 10 LTS แล้วเปลี่ยนเลขเวอร์ชันในคำสั่งและ Docker image ให้ตรงกัน

ภาพเดิมด้านล่างจึงเก็บไว้เป็นเส้นทางของ .NET 5 ส่วนตัวอย่างโค้ดจะมีทั้ง “สูตรเดิมเพื่ออ่านโปรเจกต์เก่า” และ “สูตรปี 2026 สำหรับโปรเจกต์ใหม่” ครับ

## เตรียมเครื่องมือก่อนเริ่ม

สิ่งที่ต้องมีคือ:

- .NET SDK ตามเวอร์ชันของโปรเจกต์
- Docker Desktop หรือ Docker Engine
- Editor ที่ถนัด เช่น Visual Studio, VS Code หรือ Rider
- Terminal หนึ่งหน้าต่าง

เช็กว่าเครื่องพร้อมหรือยัง:

```bash
dotnet --info
docker version
```

ถ้ากำลังดูแลระบบเก่า ให้ติดตั้ง SDK ที่โปรเจกต์ต้องใช้แยกจาก Runtime และวางแผนอัปเกรด อย่าฝืนเอา Image ที่หมดซัพพอร์ตไปวิ่ง Production เพราะมันเหมือนใช้รถที่ศูนย์ประกาศเลิกผลิตอะไหล่แล้ว—วันนี้อาจยังสตาร์ตติด แต่วันมีช่องโหว่จะลำบากครับ

## ทางลัดในปี 2026 ด้วย .NET CLI

ถ้าสร้างโปรเจกต์ใหม่ เราใช้ CLI ได้เลย:

```bash
mkdir WeatherApi
cd WeatherApi
dotnet new webapi
dotnet run
```

Terminal จะแสดง URL ที่แอปกำลัง Listen อยู่ เปิด URL นั้นหรือทดสอบด้วย `curl` ตาม Endpoint ที่ Template สร้างให้

```bash
curl http://localhost:5000/weatherforecast
```

Port จริงอาจต่างกัน ให้ยึดค่าจาก Output ของ `dotnet run` อย่าท่องเลขจนกลายเป็นความเชื่อ เพราะ Template และ Launch Profile เปลี่ยนได้ครับ

## Dockerfile แบบ Multi Stage ทำไมถึงสำคัญ

เราต้องใช้ SDK ตอน Restore และ Build แต่ตอนรันจริงต้องการเพียง ASP.NET Runtime ถ้าเอา SDK ทั้งกล่องไป Production Image จะใหญ่เกินจำเป็น เหมือนขนทั้งครัวไปส่งข้าวกล่องหนึ่งกล่อง

ภาพเดิมแสดงการสร้าง `Dockerfile` ในโปรเจกต์

![Image 6](https://miro.medium.com/v2/resize:fit:531/1*QrN77Gksugp8ftX6QpEuXQ.png)

สำหรับ .NET 5 สูตรเดิมมีโครงแบบนี้:

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:5.0 AS build
WORKDIR /src
COPY *.csproj ./
RUN dotnet restore
COPY . ./
RUN dotnet publish -c Release -o /app/publish --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:5.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "net5api.dll"]
```

ส่วนโปรเจกต์ใหม่ในปี 2026 เปลี่ยนเป็น .NET 10 LTS และใช้ Port 8080 ซึ่งเป็นค่าที่เข้ากับ Container image รุ่นใหม่:

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src

COPY *.csproj ./
RUN dotnet restore

COPY . ./
RUN dotnet publish -c Release -o /app/publish --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
EXPOSE 8080

COPY --from=build /app/publish .
USER app
ENTRYPOINT ["dotnet", "WeatherApi.dll"]
```

อย่าลืมเปลี่ยน `WeatherApi.dll` ให้ตรงกับชื่อ Assembly ของโปรเจกต์ จุดที่เพิ่มมาอย่าง `USER app` ช่วยให้ Process ไม่ต้องรันเป็น root ภายใน Container ซึ่งเป็นค่าเริ่มต้นด้านความปลอดภัยที่ดีกว่า

สร้าง `.dockerignore` ด้วย เพื่อไม่ส่งไฟล์ไม่จำเป็นเข้า Build Context:

```text
bin/
obj/
.git/
.vs/
.vscode/
Dockerfile*
README.md
```

## Build Image แล้วเปิด Container

Build จากโฟลเดอร์เดียวกับ Dockerfile:

```bash
docker build -t weather-api:local .
```

คำสั่งนี้จะทำสองงานต่อกัน Stage แรก Build และ Publish ส่วน Stage สุดท้ายคัดเฉพาะไฟล์ที่ต้องใช้จริงไปไว้ใน Runtime image

ภาพนี้คือผลลัพธ์จากการ Build เวอร์ชันเดิม

![Image 7](https://miro.medium.com/v2/resize:fit:700/1*xx-KVuNn_QgukMVYaQq_zA.png)

ถ้าใช้ Image .NET 10 ด้านบน ให้ Map Port แบบนี้:

```bash
docker run --rm -p 5000:8080 --name weather-api weather-api:local
```

อ่าน `5000:8080` จากซ้ายไปขวาว่า “ประตูหมายเลข 5000 ของเครื่องเรา ต่อเข้าประตู 8080 ใน Container” จากนั้นลองเปิด:

```text
http://localhost:5000/weatherforecast
```

![Image 8](https://miro.medium.com/v2/resize:fit:700/1*59pYvDE2Kax2UQnliw_1mw.png)

ถ้าเจอ JSON กลับมา ถือว่าการเดินทางจาก Source Code → Build → Image → Container → HTTP สำเร็จครบวงจรครับ

## จุดที่พลาดกันบ่อย

### ชื่อ DLL ไม่ตรง

ดูชื่อใน `.csproj` หรือไฟล์ที่ได้จาก `dotnet publish` แล้วแก้ `ENTRYPOINT` ให้ตรง อย่าเดาจากชื่อโฟลเดอร์อย่างเดียว

### Port ข้างในกับข้างนอกสลับกัน

เช็กว่าแอป Listen ที่ Port ใดภายใน Container แล้วค่อย Map ด้วย `-p host:container` การมี `EXPOSE` เป็นเพียง Metadata ไม่ได้เปิด Port ให้เอง

### Restore ใหม่ทุกครั้งแม้ Dependency ไม่เปลี่ยน

แยก `COPY *.csproj` กับ `dotnet restore` ไว้ก่อน `COPY . .` เพื่อให้ Docker ใช้ Layer Cache ได้ Build รอบถัดไปจะเร็วขึ้นมาก

### เก็บ Secret ไว้ใน Image

อย่า `COPY` ไฟล์ Production secret หรือใส่รหัสผ่านใน Dockerfile ส่งค่าผ่าน Secret manager, Environment variable หรือระบบจัดการ Configuration ของ Platform ที่ Deploy แทน

### ใช้ Tag ลอยใน Production

ตอนเรียนใช้ `10.0` อ่านง่าย แต่ Pipeline จริงควรควบคุมเวอร์ชันและอัปเดต Security patch อย่างมีแผน พร้อม Scan image ก่อน Deploy

## สรุป

ความคิดหลักของบทความยังเหมือนเดิม: เราใช้ Stage ที่มี SDK เพื่อ Build แล้วส่งของที่ Publish แล้วไปอยู่ใน Runtime image ที่เล็กกว่า จากนั้น Map Port เพื่อให้โลกภายนอกคุยกับ API ได้

สิ่งที่เปลี่ยนในปี 2026 คือ .NET 5 กลายเป็นบทประวัติศาสตร์แล้ว ถ้าต้องดูแลระบบเดิม ให้ใช้บทนี้ทำความเข้าใจโครงสร้างและวางแผนอัปเกรด ถ้าเริ่มระบบใหม่ ให้เลือก .NET รุ่นที่ยังซัพพอร์ต—อย่าง .NET 10 LTS ณ เวลาที่อัปเดตบทความ—และใช้ Container แบบไม่รัน root ตั้งแต่วันแรกครับ
